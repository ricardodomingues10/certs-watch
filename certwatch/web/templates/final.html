Regras aplicadas
  • As datas comparam-se ao dia. DD/MM/AAAA nunca é trocado por MM/DD; os seriais do Excel são convertidos diretamente.
  • Cada certificado das fontes é procurado na CMDB pelo CommonName. Se o CommonName da CMDB estiver vazio, usa-se Name, Display Label ou Hostname, e o CommonName é preenchido nessa mesma linha.
  • São postos de lado (relatório de erros): sem CommonName, data vazia ou ilegível, pedidos não emitidos, certificados já expirados e nomes sem domínio.
  • CommonName existente: atualiza ValidTo e SerialNumber na linha com a data mais próxima. CommonName novo: linha nova com Global Id = x; o emissor é o configurado para CA1/CA2 e, no AVI, o Issuer_CommonName.
  • Se a fonte tiver uma data anterior à da CMDB, decide o certificado que o servidor apresenta na porta 443 (verificação do certwatch com menos de {{ settings.final_live_max_age_h }} h, ou ligação na hora). Sem resposta, ou num wildcard, a CMDB não é alterada.
  • A Description regista o que mudou ("{{ settings.final_description }} - Data de expiracao alterado de … para …").
  • Os CSV levam só as linhas novas e alteradas, com separador |, CRLF e UTF-8 sem BOM. São recusados se um certificado novo não tiver Issuer, IssuerName e SerialNumber, ou se IssuerName + SerialNumber se repetir.
  • Diferenças em relação ao workflow: uma data vazia na fonte vai para o relatório de erros; ValidTo e SerialNumber só contam como alterados se mudarem de facto.
